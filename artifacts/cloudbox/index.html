Project overview

CloudBox demonstrates block-based file operations and explains how a static documentation site can be delivered from private Amazon S3 through CloudFront.

CATEGORY · CLOUD COMPUTING MINI-PROJECT

Objectives

  • Split real files into configurable blocks.
  • Encrypt and authenticate blocks with AES-256-GCM.
  • Download the encrypted package and a separate key.
  • Decrypt and reconstruct the original file.
  • Document private S3, CloudFront, OAC, and HTTPS setup.

The system in one view

Six capabilities. Two security boundaries.

Browser cryptography protects file contents; origin controls govern delivery of the static site and stored objects.

Secure File Processing

Divide a real file into ordered, configurable blocks in the browser for the encryption workflow.

Encrypted Block Storage

AES-256-GCM authenticates each encrypted block. The key is saved separately from the package.

Cloud Object Storage

Amazon S3 can store static site assets and encrypted packages behind a private bucket policy.

Global Content Delivery

CloudFront can cache and distribute static content from edge locations closer to visitors.

HTTPS Protection

TLS protects traffic in transit; a CloudFront viewer policy can redirect HTTP requests to HTTPS.

File Reconstruction

Authenticate and decrypt blocks in their saved order, then verify the original byte size.

Workflow

From source file to reconstructed output.

Encryption and reconstruction happen at the client in the learning workflow. Delivery infrastructure is a separate deployment concern.

Useful boundaries

What this prototype does not claim.

No authenticated upload API

CloudBox does not provide identity, authorization, signed uploads, or a server-side upload endpoint. Encrypting a file locally does not create those services.

No deployment implied

CloudFront and private S3 are an architecture target. This local site does not contain real AWS URLs, credentials, or a provisioned bucket.
