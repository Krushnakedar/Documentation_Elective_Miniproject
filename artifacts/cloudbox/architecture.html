CloudBox / Architecture
Two paths, clearly separated

Architecture

Website delivery and file confidentiality solve different problems. The first controls how static assets reach a browser; the second protects the bytes of a selected file.

Path 01 · web delivery

Public edge. Private origin.

CloudFront serves the static site over HTTPS. OAC signs origin requests so the S3 bucket can remain private.

Trust boundary: the bucket policy should grant the intended CloudFront distribution access, not anonymous public reads. No bucket or distribution is configured by this documentation site.

Why OAC

Origin Access Control lets CloudFront authenticate requests to an S3 origin. This keeps origin access explicit and supports a private bucket policy.

What HTTPS covers

HTTPS protects network traffic between browser and delivery endpoint. It does not encrypt an object at rest by itself or replace client-side file encryption.

Path 02 · file security

Transform the bytes before they leave the browser.

The prototype models chunk-based encryption and reconstruction. A practical package format must preserve ordering and metadata reliably.

→

→

→

→
Object / CDNstorage and delivery

On retrieval: download package → supply the separately-held key → authenticate and decrypt each block → restore original order → reconstruct the output file.

Segmentation

Bound memory use and make block count explicit. Chunking alone is not encryption and does not guarantee resumable transfer.

Authenticated encryption

GCM detects tampering during decryption. Nonces must be unique for a key, and every block's authentication must succeed.

Separate key material

The encrypted package must not embed a casually recoverable raw key. Key custody and sharing remain user responsibilities in this prototype.

Important boundary

There is no authenticated upload API.

Static site, not a storage control plane.

This frontend does not mint credentials, authenticate users, authorize object access, or issue presigned uploads. A CloudFront distribution may deliver configured objects, but safe upload requires a separately designed identity and authorization service. Never put AWS credentials in browser code.
